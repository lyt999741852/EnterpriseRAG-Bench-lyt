# R11.F raw-miss alternate embedding 隔离对照（2026-08-28）

## 目的与边界

R11.D/E 表明当前 BGE 384 维 dense 和 title/text BM25 都难以把目标带入前排。本实验不写 ES、不重建全库索引，也不把 1792 维向量查询现有 384 维字段；仅取当前 BGE dense top-300 与 BM25 top-300 的固定候选文本，加上 5 个目标文档 chunk，调用 Conan embedding API（1792 维）计算问题—文本 cosine，观察替代表征的相对排序信号。

为满足 Conan 单条 512-token 限制，候选文本统一截断为 1000 字符；因此这是可行性筛查，不是全库召回率评测。

## 结果

| 题目 | 候选池规模 | Conan 目标 rank（目标 chunk） | 最高 cosine |
|---|---:|---:|---:|
| qst_0116 | 591 | 3、77 | 0.8150 |
| qst_0184 | 562 | 539、555 | 0.7100 |
| qst_0231 | 587 | 235、305 | 0.7768 |
| qst_0251 | 591 | 7 | 0.8417 |
| qst_0298 | 596 | 30、527、541、574 | 0.7747 |

3/5 目标进入 top-30，且 `qst_0116`、`qst_0251`、`qst_0298` 的目标 cosine 明显排在候选前列；`qst_0184` 仍在 539 位，说明替代 embedding 也不是所有题通用解决方案。所有请求均返回 1792 维，cosine 已对向量长度归一化。

## 结论与下一步

R11.F 不直接放行主链，但给出比字段权重调整更强的方向信号：问题可能来自 BGE-small 对企业长文本/事件关系的表征不足。下一步应建立小规模隔离 1792 维索引（只覆盖诊断所需文档或受控子集），实际跑 ES kNN 召回并与 BGE 对照；若全库重建成本可接受，再评估 500 题快照。Conan 1792 维必须配套新索引，不能混查当前 `enterprise-rag-bge-small-v1` 的 384 维字段。
